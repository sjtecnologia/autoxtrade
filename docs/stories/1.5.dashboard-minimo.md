# Story 1.5: Dashboard Mínimo (Next.js) com Health Status

## Status

Draft

## Story

**As a** owner do autoxtrade,
**I want** um dashboard web acessível via HTTPS no VPS com tela inicial mostrando status de saúde do sistema,
**so that** eu possa verificar se todos os serviços estão rodando corretamente.

## Acceptance Criteria

1. Projeto Next.js inicializado com TailwindCSS, dark mode configurado por padrão
2. Tela de status exibe: status de cada serviço (backend, database, redis) com indicador verde/vermelho
3. Tela exibe versão do sistema e timestamp da última atualização
4. Nginx configurado como reverse proxy com HTTPS (Let's Encrypt) apontando para o VPS
5. Dashboard acessível via browser em `https://[domínio-ou-IP]` sem erros SSL
6. Conexão WebSocket estabelecida e exibindo indicador de conexão ativa no dashboard

## Dev Notes

**Design tokens definidos no Front-End Spec** (`docs/front-end-spec.md`):
```css
:root {
  --bg-base: #0d1117;
  --bg-surface: #161b22;
  --bg-elevated: #1c2128;
  --border: #30363d;
  --text-primary: #e6edf3;
  --text-secondary: #8b949e;
  --color-profit: #3fb950;
  --color-loss: #f85149;
  --color-warning: #d29922;
  --color-info: #58a6ff;
}
```

**Tipografia:** JetBrains Mono para todos os valores numéricos (preços, P&L, percentuais).

**Variáveis de ambiente Next.js:**
```bash
NEXT_PUBLIC_API_URL=https://<domínio>/api/v1
NEXT_PUBLIC_WS_URL=wss://<domínio>/ws
NEXT_PUBLIC_APP_VERSION=1.0.0
```
Variáveis sem `NEXT_PUBLIC_` não são expostas ao cliente.

**Autenticação no WebSocket:** passar token como query param na URL de conexão:
```typescript
const ws = new WebSocket(`${WS_URL}?token=${token}`);
```
O backend verifica o token na handshake e rejeita conexões inválidas.

**NUNCA** armazenar token em `sessionStorage` de forma permanente em produção — para MVP pessoal, `localStorage` é aceitável pois não há multi-usuário.

**Nginx reverse proxy** — regras principais:
```nginx
location /api/ { proxy_pass http://backend:8000; }
location /ws    { proxy_pass http://backend:8000; proxy_http_version 1.1;
                  proxy_set_header Upgrade $http_upgrade;
                  proxy_set_header Connection "upgrade"; }
location /      { proxy_pass http://frontend:3000; }
```
Configuração completa: `docs/fullstack-architecture.md` seção 6.3

### Testing

**Framework:** verificação manual no browser + inspeção de rede

Testes automatizados de frontend (Jest/Playwright) não são obrigatórios para MVP desta story. Validação por:
- Abrir `https://<domínio>` no Chrome e Firefox (últimas 2 versões — NFR7)
- Verificar: dark mode, cards de status verdes, indicador WS ativo
- Verificar: sem erros no console do browser
- Verificar: certificado SSL válido (cadeado verde no browser)
- Verificar: redirecionamento HTTP → HTTPS funcionando
