# Story 2.1: Connector Binance via CCXT/Freqtrade

## Status

Draft

## Story

**As a** engine de trading,
**I want** conectar à API da Binance de forma autenticada e buscar dados de mercado em tempo real,
**so that** o sistema tenha acesso a preços, orderbooks e possa executar ordens.

## Acceptance Criteria

1. Credenciais da Binance (API key + secret) carregadas de variável de ambiente — nunca hardcoded
2. Conexão estabelecida com sucesso: chamada à API da Binance retorna dados da conta sem erro
3. Sistema busca OHLCV em tempo real via WebSocket para pares configurados (ex: BTC/USDT, ETH/USDT)
4. Sistema busca saldo disponível por ativo e expõe via endpoint `GET /api/v1/balance`
5. Limite de rate da API da Binance respeitado; sistema implementa backoff exponencial em caso de erro 429
6. Modo paper trading configurável: quando ativo, ordens são simuladas localmente sem chamar API de ordens da Binance
7. Testes de integração com mocks da API da Binance passando

## Dev Notes

**CCXT vs Freqtrade:** O projeto usa CCXT diretamente para o connector da Binance (maior controle e simplicidade). Freqtrade é usado como referência para download de dados históricos (CLI `freqtrade download-data`) e como inspiração para estrutura de strategy, mas não como runtime em produção. Conforme ADR-002 (`docs/fullstack-architecture.md` seção 9).

**CCXT Pro para WebSocket:**
```python
import ccxt.pro as ccxtpro

async def stream_ohlcv(self, symbol: str, timeframe: str = "5m"):
    while True:
        ohlcv = await self.exchange.watch_ohlcv(symbol, timeframe)
        # ohlcv = [[timestamp, open, high, low, close, volume], ...]
        last_candle = ohlcv[-1]
        await redis.setex(f"price:{symbol}", 5, str(last_candle[4]))  # last close
        await redis.publish("market_data", json.dumps({"symbol": symbol, "price": last_candle[4]}))
```

**Backoff exponencial para rate limiting:**
```python
import asyncio

async def with_retry(coro, max_retries=5):
    for attempt in range(max_retries):
        try:
            return await coro
        except ccxt.RateLimitExceeded:
            wait = min(60, 2 ** attempt)
            log.warning("rate_limit_hit", wait_seconds=wait, attempt=attempt)
            await asyncio.sleep(wait)
    raise Exception("Max retries exceeded")
```

**Variáveis de ambiente utilizadas:**
```bash
BINANCE_API_KEY=<chave>
BINANCE_API_SECRET=<secret>
BINANCE_PAPER_MODE=true          # true em desenvolvimento, false em produção

```

**Segurança (OWASP A01/A02):**
- API keys NUNCA em código-fonte ou logs
- IP Whitelist configurado na Binance (pré-requisito Story 0.1)
- Permissão somente TRADE (sem withdrawal) — verificado no pré-requisito

**Cache Redis:**
```
Key: "price:BTC/USDT" → "287450.00" (string, TTL 5s)
Key: "ohlcv:BTC/USDT:5m" → JSON serializado dos últimos 200 candles (TTL 10s)
Channel: "market_data" → pub/sub para broadcast ao WebSocket
```

### Testing

**Framework:** pytest + pytest-asyncio + respx (mock HTTP)

**Localização:** `backend/tests/integration/test_binance_connector.py`

**Cobertura mínima:** não definida explicitamente para connector, mas mock de todos os cenários críticos é obrigatório (conexão, rate limit, paper mode).

**Exemplo de teste com mock (da arquitetura seção 10.3):**
```python
@pytest.fixture
def mock_binance(respx_mock):
    respx_mock.get("https://api.binance.com/api/v3/account").mock(
        return_value=httpx.Response(200, json={"balances": [{"asset": "USDT", "free": "1000"}]})
    )
    return respx_mock

@pytest.mark.asyncio
async def test_connector_connects(mock_binance):
    connector = BinanceConnector()
    await connector.connect()
    assert connector.is_connected is True
```
