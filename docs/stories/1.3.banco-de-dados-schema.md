# Story 1.3: Banco de Dados — Schema Inicial e Migrações

## Status

Draft

## Story

**As a** sistema autoxtrade,
**I want** o schema inicial do banco de dados criado com suporte a migrações,
**so that** os dados de operações, modelos e configurações sejam persistidos de forma estruturada e evolutiva.

## Acceptance Criteria

1. Alembic configurado para gerenciamento de migrações PostgreSQL
2. Tabelas iniciais criadas: `trades`, `ml_models`, `bot_config`, `equity_snapshots`, `trade_events`, `config_audit_log`
3. Schema da tabela `trades` inclui todos os campos definidos na arquitetura (id, market, symbol, side, status, mode, entry_price, exit_price, quantity, pnl_net, pnl_pct, stop_loss, take_profit, open_at, close_at, close_reason, model_version, ml_confidence, risk_pct, etc.)
4. Schema da tabela `bot_config` inclui: market, is_active, mode, max_open_trades, risk_per_trade_pct, max_drawdown_pct, drawdown_status, etc.
5. Migração inicial executada com sucesso; `alembic current` mostra revisão aplicada
6. Seeds com configuração padrão inseridos na tabela `bot_config` (mercado CRIPTO, mode=paper, is_active=False)

## Tasks / Subtasks

- [ ] Configurar SQLAlchemy + conexão async (AC: 1)
  - [ ] Criar `backend/database.py`: engine assíncrono com `asyncpg`, session factory, `get_db` dependency
  - [ ] Usar `postgresql+asyncpg://` URL a partir de `settings.DATABASE_URL`
  - [ ] Configurar pool de conexões: `pool_size=5`, `max_overflow=10`
- [ ] Criar modelos SQLAlchemy (AC: 2, 3, 4)
  - [ ] `backend/models/trade.py` → modelo `Trade` com todos os campos da tabela `trades` + índices
  - [ ] `backend/models/ml_model.py` → modelo `MLModel` com todos os campos da tabela `ml_models`
  - [ ] `backend/models/bot_config.py` → modelo `BotConfig` com todos os campos
  - [ ] `backend/models/equity_snapshot.py` → modelo `EquitySnapshot`
  - [ ] `backend/models/trade_event.py` → modelo `TradeEvent` com FK para `Trade`
  - [ ] `backend/models/config_audit_log.py` → modelo `ConfigAuditLog`
  - [ ] `backend/models/__init__.py` → importa todos os modelos (necessário para Alembic detectar)
- [ ] Configurar Alembic (AC: 1, 5)
  - [ ] `alembic init alembic` na raiz do backend
  - [ ] Editar `alembic/env.py`: importar modelos + configurar `target_metadata` e URL assíncrona
  - [ ] Gerar migração inicial: `alembic revision --autogenerate -m "initial_schema"`
  - [ ] Revisar migração gerada: confirmar que todos os campos e índices estão corretos
  - [ ] Executar: `alembic upgrade head`
  - [ ] Verificar: `alembic current` mostra hash da revisão
- [ ] Criar seeds iniciais (AC: 6)
  - [ ] Script `backend/scripts/seed_db.py`: inserir `BotConfig` padrão para `CRIPTO` (paper mode, is_active=False, risk 1%, max_drawdown 15%, max_open_trades 3)
  - [ ] Executar seed após primeira migração
- [ ] Adicionar task de verificação de backup (AC: complementar — NFR9)
  - [ ] Criar `scripts/backup_db.sh`: `pg_dump` do banco para arquivo `.sql.gz` com timestamp
  - [ ] Testar restore: `psql < backup.sql` em banco temporário para validar integridade

## Dev Notes

**Schema completo de todas as tabelas** está em `docs/fullstack-architecture.md` seção 2.1. Usar o SQL exato como referência para os campos e tipos.

**Campos críticos da tabela `trades`:**
```python
class Trade(Base):
    __tablename__ = "trades"
    id = Column(BigInteger, primary_key=True, autoincrement=True)
    market = Column(String(10), nullable=False)   # 'CRIPTO', 'B3', 'FOREX'
    exchange = Column(String(30), nullable=False)  # 'binance', 'mt5_xp'
    symbol = Column(String(20), nullable=False)   # 'BTC/USDT'
    side = Column(String(5), nullable=False)      # 'LONG', 'SHORT'
    status = Column(String(10), nullable=False)   # 'open', 'closed', 'cancelled'
    mode = Column(String(10), nullable=False, default='live')  # 'live', 'paper'
    entry_price = Column(Numeric(20, 8), nullable=False)
    stop_loss = Column(Numeric(20, 8), nullable=False)
    take_profit = Column(Numeric(20, 8))
    open_at = Column(TIMESTAMP(timezone=True), nullable=False)
    # ... demais campos (ver arquitetura seção 2.1)
```

**Campos críticos da tabela `bot_config`:**
```python
class BotConfig(Base):
    __tablename__ = "bot_config"
    market = Column(String(10), nullable=False, unique=True)  # chave natural
    is_active = Column(Boolean, nullable=False, default=False)
    mode = Column(String(10), nullable=False, default='paper')
    risk_per_trade_pct = Column(Numeric(5, 2), nullable=False, default=1.0)
    max_open_trades = Column(SmallInteger, nullable=False, default=3)
    max_drawdown_pct = Column(Numeric(5, 2), nullable=False, default=15.0)
    drawdown_status = Column(String(10), nullable=False, default='OK')  # OK, WARNING, PAUSED
```

### Testing

**Framework:** pytest + pytest-asyncio

**Localização dos testes:** `backend/tests/integration/test_database.py`

**Padrão de testes para este módulo:**
```python
@pytest.mark.asyncio
async def test_create_trade(db_session):
    trade = Trade(market="CRIPTO", symbol="BTC/USDT", side="LONG",
                  entry_price=Decimal("287450"), quantity=Decimal("0.001"),
                  stop_loss=Decimal("282000"), status="open", mode="paper",
                  open_at=datetime.utcnow(), exchange="binance")
    db_session.add(trade)
    await db_session.commit()
    await db_session.refresh(trade)
    assert trade.id is not None
```

**Fixture de DB para testes:** usar banco PostgreSQL em memória via Docker (testcontainers) ou banco de teste separado.

**Cobertura mínima:** não há cobertura obrigatória para modelos de dados/migrações — validação é por execução real das migrações.
