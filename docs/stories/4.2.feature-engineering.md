# Story 4.2: Engenharia de Features e Indicadores Técnicos

## Status

Draft

## Story

**As a** modelo ML,
**I want** calcular features baseadas em indicadores técnicos a partir dos dados OHLCV,
**so that** o modelo tenha sinais relevantes para classificar a direção do preço.

## Acceptance Criteria

1. Features implementadas: RSI(14), MACD(12,26,9), Bollinger Bands(20,2), EMA(9,21,50,200), ATR(14), OBV (On-Balance Volume), Stochastic(14,3)
2. Features de regime de mercado: ADX(14) para força de tendência, variação de volume (volume atual vs média 20 períodos)
3. Target (label) calculado: retorno futuro em N candles; binarizado em LONG (retorno > +0.5%), SHORT (retorno < -0.5%), NEUTRO (entre -0.5% e +0.5%)
4. Features normalizadas com StandardScaler; scaler salvo junto ao modelo para uso em inferência
5. Pipeline de features reproduzível: mesma entrada → mesma saída, sem data leakage
6. Testes unitários para cada indicador com valores conhecidos

## Tasks / Subtasks

- [ ] Implementar FeatureEngineer (AC: 1, 2, 5)
  - [ ] `backend/ml/feature_engineer.py`: classe `FeatureEngineer`
  - [ ] Método `calculate_features(df)`:
    - Input: DataFrame OHLCV com colunas `open, high, low, close, volume`
    - Calcular todos os indicadores usando `ta` (biblioteca `ta-lib` ou `pandas-ta`)
    - RSI(14): `ta.momentum.RSIIndicator(close, window=14).rsi()`
    - MACD(12,26,9): linha MACD, linha signal, histograma
    - Bollinger Bands(20,2): upper, middle, lower, %B, bandwidth
    - EMA(9), EMA(21), EMA(50), EMA(200)
    - ATR(14): Average True Range
    - OBV: On-Balance Volume
    - Stochastic(14,3): %K e %D
    - ADX(14): Average Directional Index (força da tendência)
    - Volume ratio: `volume / volume.rolling(20).mean()`
  - [ ] Remover linhas com NaN (primeiras N linhas sem indicadores calculados)
  - [ ] Retornar DataFrame com features calculadas + colunas OHLCV originais
- [ ] Implementar cálculo do target (label) (AC: 3)
  - [ ] Método `calculate_target(df, forward_candles=5, threshold=0.005)`:
    - Calcular retorno futuro: `future_return = (close.shift(-forward_candles) - close) / close`
    - Aplicar thresholds: LONG (+0.5%), SHORT (-0.5%), NEUTRO (entre os dois)
    - `target = np.where(future_return > threshold, "LONG", np.where(future_return < -threshold, "SHORT", "NEUTRO"))`
    - Remover últimas N linhas sem target válido
    - Retornar DataFrame com coluna `target`
- [ ] Implementar normalização (AC: 4)
  - [ ] Método `fit_transform(df_features)`:
    - Separar features numéricas das colunas de target e OHLCV
    - Treinar `StandardScaler` nas features numéricas
    - Salvar scaler: `joblib.dump(scaler, f"ml/models/{version}_scaler.pkl")`
    - Retornar DataFrame normalizado + scaler
  - [ ] Método `transform(df_features, scaler)`:
    - Aplicar scaler existente (para inferência em produção)
    - Retornar DataFrame normalizado
- [ ] Listar features usadas (AC: 5)
  - [ ] `FEATURE_COLUMNS`: constante com lista ordenada de todas as features
  - [ ] Salvar lista no banco junto ao modelo em `ml_models.feature_list` (JSONB)
  - [ ] Garantir que mesma lista é usada em treino e inferência
- [ ] Escrever testes unitários (AC: 6)
  - [ ] `backend/tests/unit/test_feature_engineer.py`
  - [ ] Usar `backend/tests/fixtures/sample_ohlcv.parquet` como fixture
  - [ ] Para cada indicador: verificar valor calculado contra valor esperado manual
  - [ ] Testar target LONG quando retorno futuro = +2% (acima de +0.5%)
  - [ ] Testar target SHORT quando retorno futuro = -1.5% (abaixo de -0.5%)
  - [ ] Testar target NEUTRO quando retorno futuro = 0.2%
  - [ ] Testar que não há data leakage: features do candle T não usam dados de T+1

## Dev Notes

**Biblioteca de indicadores:** usar `pandas-ta` (mais simples e pythônico que TA-Lib):
```bash
pip install pandas-ta
```
TA-Lib requer compilação de biblioteca C — `pandas-ta` é pure Python e mais fácil de instalar em Docker.

**Cálculo dos indicadores com pandas-ta:**
```python
import pandas_ta as ta

# Adicionar todos os indicadores ao DataFrame
df.ta.rsi(length=14, append=True)           # RSI_14
df.ta.macd(fast=12, slow=26, signal=9, append=True)  # MACD_12_26_9, etc.
df.ta.bbands(length=20, std=2, append=True)  # BBL, BBM, BBU, BBB, BBP
df.ta.ema(length=9, append=True)
df.ta.ema(length=21, append=True)
df.ta.ema(length=50, append=True)
df.ta.ema(length=200, append=True)
df.ta.atr(length=14, append=True)
df.ta.obv(append=True)
df.ta.stoch(k=14, d=3, append=True)
df.ta.adx(length=14, append=True)
df["volume_ratio"] = df["volume"] / df["volume"].rolling(20).mean()
```

**Target sem data leakage:**
```python
# CORRETO: usar shift negativo para olhar para o FUTURO
future_return = (df["close"].shift(-5) - df["close"]) / df["close"]

# ERRADO (data leakage): usar informação futura durante treino
# future_return = df["close"].rolling(5).mean() — NUNCA usar em features
```
**CRÍTICO:** Features devem ser calculadas usando APENAS dados até o candle T inclusive. Nenhuma feature deve usar close[T+1] ou além.

### Testing

**Framework:** pytest

**Localização:** `backend/tests/unit/test_feature_engineer.py`

**Cobertura obrigatória:** 80% em `backend/ml/feature_engineer.py`

**Exemplo de testes:**
```python
from ml.feature_engineer import FeatureEngineer, FEATURE_COLUMNS
import pandas as pd
import numpy as np

@pytest.fixture
def sample_ohlcv():
    return pd.read_parquet("tests/fixtures/sample_ohlcv.parquet")

def test_all_features_calculated(sample_ohlcv):
    fe = FeatureEngineer()
    df = fe.calculate_features(sample_ohlcv)
    for col in FEATURE_COLUMNS:
        assert col in df.columns, f"Feature {col} missing"

def test_target_long_on_positive_return():
    fe = FeatureEngineer()
    # Criar série onde close cresce 2% em 5 candles
    closes = pd.Series([100.0, 101.0, 102.0, 101.5, 102.0, 102.5])
    df = pd.DataFrame({"close": closes})
    result = fe.calculate_target(df, forward_candles=5, threshold=0.005)
    assert result["target"].iloc[0] == "LONG"
```
