# Story 6.2: Checklist de Segurança e Go-Live com Capital Real

## Status

Draft

## Story

**As a** owner do autoxtrade,
**I want** executar um checklist de segurança completo antes de ativar o bot com capital real,
**so that** o risco de perda por configuração errada ou vulnerabilidade seja minimizado ao máximo.

## Acceptance Criteria

1. Checklist de segurança 100% concluído antes de qualquer operação com capital real
2. Capital inicial máximo de R$500 (USDT equivalente) para o primeiro mês de live trading
3. Apenas BTC/USDT habilitado no primeiro go-live (par com maior liquidez e menor risco de manipulação)
4. Primeira operação real gera notificação Telegram especial: "🚀 PRIMEIRO TRADE REAL — [detalhes]"
5. Monitoramento intensivo nas primeiras 24 horas: owner verifica dashboard a cada hora

## Tasks / Subtasks

- [ ] Executar checklist de segurança (AC: 1)
  - [ ] **API Keys Binance:**
    - [ ] Chaves configuradas com permissão apenas para trading (sem saque habilitado)

    - [ ] Nenhuma credencial em código-fonte ou logs
  - [ ] **Infraestrutura:**
    - [ ] Nginx com HTTPS (Let's Encrypt) ativo e redirecionando HTTP→HTTPS
    - [ ] Firewall VPS: apenas portas 80, 443 e SSH abertas
    - [ ] Containers Docker em estado "healthy" (`docker compose ps`)
  - [ ] **Configuração do bot:**
    - [ ] `bot_config.mode = "live"` (atualizar de "paper" para "live")
    - [ ] `bot_config.paper_balance` = null (ou ignorado em modo live)
    - [ ] Capital máximo: depositar somente R$500 em USDT na conta Binance
    - [ ] `risk_per_trade_pct = 0.01` (1% = R$5 por trade — conservador)
    - [ ] `max_open_positions = 1` (apenas 1 posição simultânea no início)
  - [ ] **Modelo ML:**
    - [ ] Modelo ativo no banco com Profit Factor ≥ 1.3 no backtesting

  - [ ] **Backups:**

  - [ ] Alterar `bot_config.mode = "live"` via endpoint ou diretamente no banco
  - [ ] Confirmar que apenas `BTC/USDT` está na lista de símbolos monitorados

  - [ ] Em `backend/notifications/templates.py`: adicionar template `first_real_trade`:

## Dev Notes

**Checklist de segurança mínima (OWASP + trading):**

| Item | Verificação | Critério de passagem |
|---|---|---|
| API Keys sem saque | Painel Binance → API Management | Checkbox "Enable Withdrawals" DESMARCADO |
| IP Whitelist | Painel Binance → API Management | IP do VPS listado |
| HTTPS ativo | `curl -I https://seu-dominio.com` | Status 200, header `Strict-Transport-Security` |
| `.env` não no git | `git log --all --full-history -- .env` | Sem resultados |
| Bearer token forte | `len(token) >= 64 chars` | `echo -n $BEARER_TOKEN \| wc -c` >= 64 |
| Portas fechadas | `nmap seu-vps-ip` | Apenas 22, 80, 443 abertas |
| Containers healthy | `docker compose ps` | Estado "healthy" para todos |

**Por que apenas R$500 inicial?**
- Limitar exposição a bugs não encontrados no paper trading
- Profit Factor do modelo em live pode diferir do backtesting (overfitting residual)
- Permite verificar o ciclo completo com risco controlado antes de escalar capital

**Como alterar modo para live:**
```sql
UPDATE bot_config 
SET mode = 'live', is_active = true, paper_balance = NULL
WHERE market = 'CRIPTO';
```
Ou via endpoint PATCH existente.

**Backup do PostgreSQL:**
```bash
# Adicionar ao crontab do VPS (diário às 01h)
0 1 * * * docker compose exec postgres pg_dump -U postgres autoxtrade | gzip > /backups/autoxtrade-$(date +%Y%m%d).sql.gz
```
